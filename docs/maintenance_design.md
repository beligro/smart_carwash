# Обслуживание оборудования: учёт ремонтов, ресурса узлов и предиктивное ТО

> Статус: **дизайн / блюпринт** (без кода). Документ фиксирует логику для последующей
> реализации и ревью. Точный список узлов готовит Макс (см. раздел «Открытые вопросы»).

## 1. Цель

Перейти от учёта «ТО по боксам» к **журналу обслуживания по аппаратам и боксам с разбивкой
по узлам**, чтобы:

- видеть, какой узел изнашивается через сколько моточасов (резинки ≈ X мч, помпа ≈ Y мч);
- прогнозировать отказы и менять узлы превентивно;
- держать на складе нужный запас запчастей (расход денег сверяем с 1С);
- снизить простой и расходы.

Старт статистики — **в момент возврата бокса из сервиса в работу**: Макс выбирает из списка,
что заменили/отремонтировали. Чем раньше начнём логировать, тем раньше появится аналитика.

## 2. Ключевой принцип: два носителя износа, два одометра

Износ несут **два независимых носителя**, и считаются они от проданного времени, но по-разному
ведут себя при ротации аппаратов:

| | Аппарат (насос в аппаратной) | Бокс (точка использования) |
|---|---|---|
| **Узлы** | помпа, сальники/манжеты, клапаны, редуктор, электромотор, подшипники, ремень, масло | шланг РВД, пистолет ВД, форсунка, контактор, автомат, пускатель |
| **Одометр** | моточасы аппарата | моточасы бокса |
| **При ротации** | **едут** с аппаратом | **остаются** в боксе |

- **Моточасы бокса** = Σ проданного времени всех завершённых сессий бокса / 60.
  Монотонные, ротация на них не влияет. → ресурс пистолета, РВД, форсунки, электрики бокса.
- **Моточасы аппарата** = пожизненная наработка насоса, **следующая за ним** сквозь ротации.
  → ресурс узлов помпы/мотора.

Топология: **1 аппарат ↔ 1 бокс** в каждый момент времени. Ротация = переключение, какой
аппарат питает какой бокс. Пистолет и РВД физически в боксе, аппарат — отдельно в аппаратной,
поэтому при перестановке аппарата боксовые узлы остаются на месте.

## 3. Модель данных (предлагаемая)

### 3.1. `machines` (аппарат) — новая сущность
- `id`, `label` / серийник
- `current_box_number` (текущий бокс, 1:1)
- `commissioned_at` (ввод в работу)
- пожизненный одометр наработки (моточасы), **не сбрасывается**, переносится при ротации
- `last_oil_change_at`, моточасы на момент последней замены масла

### 3.2. `component_types` (справочник узлов)
- `id`, `name`
- `carrier` — **`machine` | `box`** (носитель: аппарат или бокс)
- `expected_life_hours` — ресурс в моточасах своего носителя (вычисляется по статистике)
- список финализирует Макс; на старте — предварительный (раздел 6)

### 3.3. `service_tickets` (наряд на сервис) — жизненный цикл простоя
- `id`, `box_number`, `machine_id` (аппарат на момент сервиса)
- `opened_at`, `opened_by` (кассир) + предварительная заметка/узлы
- `closed_at`, `closed_by` (Макс) + факт выполненных работ
- простой = `closed_at − opened_at`

### 3.4. `maintenance_events` (журнал событий) — расширение текущего `box_maintenance_log`
- `id`, `ticket_id`
- `carrier_ref` — ссылка на **аппарат** или **бокс** (по носителю узла)
- `component_type_id`
- `action` — **`replace` (замена) | `repair` (ремонт) | `inspect` (осмотр)**
- `motor_hours_at_event` — нужный одометр на момент закрытия наряда
  (моточасы аппарата для узлов помпы/мотора, моточасы бокса для пистолета/РВД)
- `performed_by`, `performed_at`, `comment`
- **деньги не дублируем** — стоимость и расход ведутся в 1С

## 4. Жизненный цикл наряда (двухэтапный)

Капча привязана к существующим действиям «поставить в сервис» / «вернуть в работу»:

1. **Кассир ставит бокс в сервис** → открывается наряд. Кассир предварительно выбирает из
   списка узел + носитель + короткую заметку («лопнул шланг ВД»). Бокс уходит в `maintenance`,
   стартует отсчёт простоя.
2. **Макс возвращает бокс в работу** → закрывает наряд. Указывает, что реально сделано: по
   каждому узлу — действие (заменён / отремонтирован / осмотрен) + комментарий.
   **Это и есть момент старта статистики.** Бокс возвращается, простой фиксируется.
3. Система пишет события в журнал с правильным носителем и моточасами на момент закрытия.

> Примечание: в сервис бокс в ~90% ставит кассир, вернуть в работу может только Макс.
> Поэтому предварительный ввод — на кассире, окончательный (авторитетный для статистики) — на Максе.

## 5. Замена vs ремонт (важно для расчёта ресурса)

- **Замена** → сбрасывает «часы с установки» узла. Ресурс считается из интервалов
  **между заменами** одного и того же узла.
- **Ремонт** → фиксируем факт и простой, но износ **не обнуляем** (узел тот же).

Из практики:
- **РВД**: бывает и ремонт (соединитель ВД при разрыве), и замена.
- **Электромотор**: ремонт (перемотка обмотки) или замена.
- **Помпа и её ЗЧ** (сальники, клапаны): ремонтов нет — только замена на новые.

## 6. Справочник узлов (предварительный — финализирует Макс)

> Без моделей, артикулов и цен. Макс с командой составит толковый список «что наёбывается».

**Аппарат (едет с аппаратом):**
- Помпа (в сборе)
- Сальники / манжеты
- Клапаны помпы
- Редуктор
- Электромотор
- Подшипники
- Ремень
- Масло (замена масла)

**Бокс (остаётся в боксе):**
- Шланг РВД
- Пистолет ВД
- Форсунка
- Контактор
- Автомат выключатель
- Пускатель

## 7. Аналитика (ради чего всё)

- **Ресурс узла** (раздельно по носителю):
  - узлы помпы/мотора — интервалы в **моточасах аппарата** между заменами;
  - пистолет/РВД/форсунка/электрика бокса — интервалы в **моточасах бокса**.
- **Прогноз отказа**: ресурс узла − наработка с последней замены → дата при текущем темпе.
- **План склада**: ожидаемое число замен в месяц по каждому узлу × 16 аппаратов/боксов →
  минимальный запас. Деньги/расход сверяем с 1С.
- **Дашборд**: «узлы под риском в ближайшие 2 недели» → превентивная замена.

## 8. Ввод данных

- **Админка** (страница «ТО аппаратов»): полная форма наряда; моточасы подставляются автоматически.
- **Телеграм-бот**: быстрый ввод в полевых условиях (узел + бокс/аппарат, моточасы берёт сам).

- боксовые узлы считаются на одометре бокса и при ротации не сбрасываются.

## 10. Поэтапный план

- **Фаза 1** — справочник узлов + журнал событий на возврате из сервиса (старт сбора данных).
- **Фаза 2** — сущность «аппарат» + пожизненный одометр (корректность сквозь ротации);
  перенос логики ротации на перемещение записи аппарата.
- **Фаза 3** — аналитика: ресурс узлов, прогноз отказов, рекомендации по складу.
